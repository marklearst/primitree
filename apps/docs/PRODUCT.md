# Product

## Register

brand

## Platform

web

## Users

Primitree is for design-system engineers who maintain shared token architecture across products, repositories, and teams. They need to understand what a token change affects before it ships, enforce ownership and layer boundaries, and give collaborators evidence that a change clears the rules required to ship.

## Product Purpose

Primitree turns DTCG tokens into a governed dependency graph. It checks project rules, traces aliases and dependents, and produces byte-stable build artifacts. The CLI and MCP expose graph evidence; React hooks consume the built DTCG documents and Resolver. Success means a team can change one token, know every consequence, and ship without relying on manual archaeology.

## Positioning

Govern token change. Know every consequence.

## Conversion & proof

- The primary action is to run the quickstart. The secondary path is to inspect the graph in the docs or playground.
- The line a visitor remembers after ten seconds is: “Govern token change. Know every consequence.”
- The visitor should understand, in order, that Primitree reads standard DTCG tokens, enforces layer, owner, and policy rules, traces aliases and dependents, writes byte-stable outputs, exposes graph evidence through the CLI and MCP, and provides the built tokens to React through hooks.
- Proof on hand is the working open-source repository: DTCG 2025.10 support, local-first checks, byte-stable artifacts, semantic diffs, inspectable aliases and dependents, React hooks, MCP tools, and a browser playground. Do not invent testimonials, customer logos, or adoption claims.

## Brand Personality

Rigorous, alive, assured. Primitree should feel like an expert system that makes hidden relationships legible. It can create visual excitement, but confidence comes from causality and proof rather than spectacle.

## Anti-references

The current generic dark dev-tool template is itself an anti-reference: faint grids and noise, neon haze, orbit rings, pulsing dot eyebrows, oversized decorative marks, fake Mac terminals, interchangeable bento cards, and “cool because it glows” composition. Avoid generic AI-tool marketing, dashboard collage, 3D pastel illustration, glassmorphism, purple cyber gradients, and ornamental trees that do not explain governance.

## Design Principles

1. The mechanism is the art direction. Show a real governed token relationship rather than decorating the page with tree imagery.
2. Causality over decoration. Every branch, highlight, and motion cue must explain what a change governs, traces, blocks, or ships.
3. Proof over hype. Use real Primitree concepts and reproducible outcomes; never invent social proof.
4. One shared graph, one narrative. Govern, Trace, and Ship are different views of the same token change, not unrelated feature cards.
5. Touch and keyboard are first-class. The experience must be complete on iPad, with reduced motion, keyboard navigation, and screen-reader meaning.

## Accessibility & Inclusion

Meet WCAG 2.2 AA. Preserve strong contrast, visible keyboard focus, semantic headings and controls, 44-by-44-pixel touch targets, and a complete non-pointer interaction path. Respect `prefers-reduced-motion`; removing animation must not remove information. The layout must remain usable in portrait and landscape iPad viewports without hover-dependent controls.
