FigmaVars accepts a Variables REST API response, a bare `meta` object, or a plugin export with `variables` and `collections`.

## FigmaVars Export plugin

During local development, load the [FigmaVars Export](/docs/figma-plugin) plugin from this repository:

1. Build the plugin with `pnpm --filter figmavars-plugin build`
2. In Figma, choose Plugins → Development → Import plugin from manifest
3. Select `apps/figma-plugin/dist/manifest.json`
4. Run **FigmaVars Export** and download `variables.json`

The plugin calls `getLocalVariableCollectionsAsync()` and `getLocalVariablesAsync()` in the open file. Its output uses the REST local variables response shape expected by the CLI.

## Other plugin exports

FigmaVars accepts these layouts:

- `{ meta: { variables, variableCollections } }`
- `{ variables, variableCollections }`
- `{ variables: [...], collections: [...] }`

The normalizer accepts record maps or arrays for variables and collections. Published variables responses do not contain mode values and cannot feed the build.

## Variables REST API

Figma limits the Variables REST API to Enterprise organizations. A local variables request needs `file_variables:read` and access to the file.

```bash
export FIGMA_TOKEN=figd_...
export FIGMA_FILE_KEY=AbCdEf...

figma-vars export --out variables.json
```

The hooks package also includes the `figma-vars-export` compatibility bin:

```bash
npx --package @figmavars/hooks figma-vars-export --file-key "$FIGMA_FILE_KEY"
```

Run a check before building:

```bash
figma-vars check variables.json
```

## Keep exports in version control

Commit `variables.json` when the repository needs to compare stable Figma IDs, names, types, and per-mode values across changes.

See [Semantic diffing](/docs/concepts/diffing) for how matching works.
